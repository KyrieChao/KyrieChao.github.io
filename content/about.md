我是 **Kyrie Chao**，一名计算机专业的学生，也是一名喜欢从零构建东西的开发者。

我不满足于让程序运行起来。我更关心它为什么这样运行，抽象是否合理，接口是否清晰，以及一个系统能否在不断扩展的过程中依然保持简单。

目前，我正在学习 C 语言、Linux 系统编程与嵌入式开发，也在继续积累后端开发经验。对我而言，编程不只是实现需求的手段，也是理解计算机、设计系统和验证想法的方式。

## 我在关注什么

- **系统与底层开发**：C 语言、Linux、操作系统、进程与线程、内存管理和嵌入式系统。
- **软件工程**：接口设计、模块边界、错误处理、测试，以及如何让软件更容易理解、调试和维护。
- **语言与工具**：我正在探索自己的通用编程语言 **Kria**，希望从类型系统、语法设计和运行机制开始，逐步建立一套适合自己的语言与工具体系。
- **自主构建**：我喜欢把想法变成实际可运行的项目，再通过使用、测试和重构发现问题，而不是停留在设计阶段。

## 一些项目

### [Failure](https://github.com/KyrieChao/Failure)

一个基于 Spring Boot 的验证框架。

它始于对校验 API 设计的探索，后来逐渐涉及流式调用、条件执行、延迟校验和异常定位等问题。这个项目让我持续思考：怎样设计更清晰的抽象，让使用者写出易读的代码，同时让框架本身保持可测试、可维护。

### [Chao Online Judge](https://github.com/KyrieChao/Chao-Online-Judge)

一个在线判题系统，涉及前后端开发、数据存储、消息队列以及代码执行与判题流程。

### [C-Kit](https://ck.chaokyrie.asia)

一个面向命令行的开发工具项目，也是我探索工具设计、工程交付和实际使用体验的一部分。

## 关于这个博客

这里记录我的学习过程、技术实践、设计思考，以及一些尚未形成结论的问题。

我不希望只记录最终答案，也希望保留那些走错的路、遇到的困难和后来改变的想法。比起整理出一份看起来完美的知识清单，我更希望这些记录能够真实反映一个开发者如何逐步建立自己的理解。

我仍在学习，也还没有完成自己想做的许多东西。

但我希望能够持续构建、持续验证，并让每一次实践都成为下一次尝试的基础。
